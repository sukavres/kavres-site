# MPLS 江湖恩仇录

## 江湖背景：IP 江湖的困境

早年 IP 江湖混乱不堪，各路 “数据包大侠” 仅凭 “IP 地址令牌” 闯荡，每到一个 “路由器驿站”，都要翻遍 “路由宝典”（路由表）找方向，效率低下还容易迷路（转发延迟）。更要命的是，不同门派（VPN 业务）的大侠混行，常因身份不明引发冲突（数据泄露）。

此时，“MPLS 祖师爷” 横空出世，创立 “标签心法”，给每位大侠发一枚 “标签腰牌”，从此江湖秩序大变。

## 核心门派与人物

1. **标签门（核心势力）**：掌管 “标签腰牌” 的发放与识别，核心武功是 “标签映射术”（LFIB 表）。
   - 掌门：LDP（标签分发协议），性格公允，给每位大侠分配唯一 “入腰牌”（Label in），再对应发放 “出腰牌”（Label out）。
   - 长老：RSVP-TE，脾气火爆，专管 “加急镖件”（QoS 业务），能开辟专属 “绿色通道”（LSP），避免拥堵。
2. **边缘三侠（Ingress/Egress 节点）**：负责江湖入口和出口，处理 “腰牌” 的发放与回收。
   - 入侠（Ingress）：给刚入江湖的 IP 大侠打上 “出腰牌”，明确门派（VPN）和目的地。
   - 出侠（Egress）：给即将出江湖的大侠摘下 “入腰牌”，恢复 IP 身份，指引最终归宿。
3. **中转护法（Transit 节点）**：遍布江湖的驿站守护者，不用看 “IP 令牌”，只认 “标签腰牌”，一招 “标签替换术”（入标签换出标签），就能快速指引方向，从不拖泥带水。
4. **保留长老（0-15 号标签）**：江湖元老，负责传递紧急消息（控制平面），不参与普通大侠的转发。比如 “1 号长老”（Router Alert），遇到紧急情况会叫停大侠，传递指令。

## 江湖恩怨主线

### 1. 标签门的 “唯一性铁律”

标签门有个死规矩：同一驿站（设备）的 “入腰牌”（Label in）绝不重复。一旦重复，护法就分不清该给大侠指哪条路，轻则迷路，重则引发江湖大乱（转发环路）。这是 LDP 掌门立下的铁律，违者逐出江湖。

### 2. 不同门派的 “隔离恩怨”

VPN 两大门派（红门、蓝门）势同水火，大侠们不能互通消息。标签门想出妙招：给两派大侠分配不同 “入腰牌”，哪怕目的地和路线相同，“出腰牌” 也不一样。中转护法只认腰牌不认人，确保两派大侠各走各的路，互不干扰。

### 3. 加急镖件的 “特权之争”

普通大侠（IP 包）按规矩排队，而加急镖件（语音、视频业务）想要优先通行。RSVP-TE 长老站出来，直接开辟一条 “专属密道”（LSP），给镖件发 “特殊腰牌”，所有驿站护法见牌放行，一路绿灯，这让普通大侠羡慕不已，却也无可奈何（QoS 优先级）。

### 4. 腰牌替换的 “必经之路”

大侠从 A 驿站到 D 驿站，要经过 B、C 两个中转驿站：

- A 驿站（入侠）给大侠发 “腰牌 100”（出标签），让他去 B 驿站；
- B 驿站（护法）见 “腰牌 100”（入标签），换成 “腰牌 200”（出标签），指引去 C 驿站；
- C 驿站（护法）见 “腰牌 200”（入标签），换成 “腰牌 300”（出标签），指引去 D 驿站；
- D 驿站（出侠）摘下 “腰牌 300”（入标签），大侠恢复 IP 身份，抵达目的地。

全程 “入腰牌” 和 “出腰牌” 绝不相同，这是避免江湖环路的关键 —— 要是 B 驿站把 “腰牌 100” 再发回 A 驿站，大侠就会在 A、B 之间打转，永无宁日。

## 江湖结局

MPLS “标签心法” 解决了 IP 江湖的混乱，让数据包大侠们通行无阻，不同门派和谐共处，加急镖件高效送达。虽然后来有 SDN 等 “新门派” 崛起，但 MPLS 凭借稳定的 “江湖规矩”，至今仍是骨干网络的中流砥柱，恩怨仍在继续，秩序从未崩塌～
